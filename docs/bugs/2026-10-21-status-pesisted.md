# 버그 보고: 상태를 바꿔도 저장되지 않는다

> 연습용으로 심은 버그이다. 눈으로 본 것과 호출 결과만 적었다. #5, 여기에서 해결됨.

## 요약
카드의 상태를 바꾸면 화면에서는 카드가 새 열로 옮겨 가 있다. 서버는 오류 없이 응답하지만 응답의 상태는 바꾸기 전 값이고, 새로고침하면 카드가 원래 열로 돌아온다.

## 재현 순서
1. 서버를 새로 시작하고 화면을 연다.
2. 생성 버튼으로 상태 "할 일"인 카드를 하나 만든다.
3. 카드의 상태 선택 창에서 "완료"를 고른다.
4. 카드가 "완료" 열에 보이는 것을 확인한다. 오류 문구는 뜨지 않는다.
5. 브라우저를 새로고침한다.

## 기대 동작
- 3번 뒤 카드가 "완료" 열에 있고, 5번 뒤에도 "완료" 열에 그대로 있다. (R-002 조건 1·2, R-006)
- 검토표의 SC-05, SC-06, SC-08, BR-09 가 이 동작을 확인하는 줄이다.

## 실제 동작
- 4번: 카드가 "완료" 열에 보인다.
- 5번: 카드가 "할 일" 열로 돌아와 있다.

## 증거
요청과 응답 (임시 DB 와 별도 포트로 띄운 서버에 직접 호출한 결과)

| 항목 | 값 |
|---|---|
| 요청 | `PATCH /tasks/{id}` 본문 `{"status": "DONE"}` |
| 응답 | 200, `"status": "TODO"` (보낸 값이 아니라 바꾸기 전 값) |
| 다시 조회 | `TODO` |

- 같은 서버에서 제목과 설명을 고치는 요청은 정상으로 저장되었다.
- 응답이 200 이라서 화면에는 실패 알림이 뜨지 않는다.

## 영향
- 상태 변경이 저장되지 않아 R-002 와 R-006 을 만족하지 못한다.
- 화면의 카드와 저장된 카드가 어긋난다. 실패한 변경을 보인 것처럼 남기지 않는다는 방침(USER-WORKFLOW 7-2)에 맞지 않는다.

## 확인하지 않은 것
- 브라우저의 Network 탭에서 위 요청과 응답을 직접 본 것은 아니다. 확인 필요.
- 상태 변경이 아닌 다른 동작(생성, 삭제)에는 영향이 없는지 전부 확인하지는 않았다.
- 서버가 `--reload` 없이 오래 떠 있으면 수정 전 코드로 동작한다. 재현 전에 서버를 새로 시작한다.

## 원인
- PATCH /api/tasks/{id} 로 보내 저장되지 않음
